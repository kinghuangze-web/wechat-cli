# Grok Bot、手机微信与本地群聊：执行说明

> **接收程序迁移更新：** 当前本地方案把微信轮询与 webhook 转发迁到 Windows，由 WorkBuddy 准备并交给计划任务维护；Grok Bot 仍在原执行环境处理任务，并通过原 reply / reply-image 发送回复。它没有把全部处理移到本机。完整迁移步骤见 [WINDOWS_BRIDGE.md](WINDOWS_BRIDGE.md)。迁移后不可再次启动旧云端接收程序。下文的历史路线与历史停止事件，应与这份迁移附注区分阅读。

本文供具备必要工具权限的 Agent 使用。面向读者的教程只保留打开入口、填写私密信息、扫码与真实收图等动作。

## 两条连接分别验收

```text
手机微信 ↔ 微信消息转发 ↔ Grok Bot
                              ↓ 已有本机执行工具
                       用户的 Windows 电脑
                              ↓ wechat-cli
                       本机已有的指定群记录
```

第一条连接负责从手机收任务和回复。第二条连接负责访问用户电脑上的群聊历史。只连接手机消息接口，不能自动获得群历史。

本文件描述用户提供的历史成功路线，不要求改用 OpenClaw，也不要求重建已经存在的连接。本文以 WorkBuddy 完成电脑准备，Grok Bot 为可选手机任务入口。

## 先确认现有条件

- Grok Bot 是否有本机执行工具，能在保存微信记录的那台电脑运行命令。
- 执行身份能否访问已经初始化的 CLI 配置；避免在云电脑或另一个用户目录下创建空配置。
- 手机账号是否有可用的 ClawBot/相应绑定入口。
- Grok Bot 当前是否支持被触发的 routine、私密输入及必要的后台执行。入口与能力以当前实际版本为准。

缺少能力时，说明具体缺项；不要伪造菜单、凭据输入框或二维码，不以提示词替代执行能力。不要自动部署一套未经用户要求的替代系统。

## 历史路线的执行顺序

1. 依据官方资料确认当前协议。历史实现参考腾讯 `@tencent-weixin/openclaw-weixin` 源码，使用 iLink 的 `getupdates` 长轮询和 `sendmessage` 发送；官方项目入口为 [Tencent/openclaw-weixin](https://github.com/Tencent/openclaw-weixin)，具体协议见该项目当前文档。本教程不复制或发布用户的转发程序。
2. 在具备相应能力的 Grok Bot 环境创建消息触发入口。由用户在实际面板复制入口链接和 key，使用产品提供的私密输入工具保存；没有私密输入工具则停止该凭据步骤，不索取聊天明文。
3. 在已有约定执行环境准备转发与回复，限定绑定用户，保留运行状态与恢复方法。历史路线只需要出站 HTTPS；不要新增公网监听。
4. 通过实际协议生成绑定二维码与可用的备用入口，用户扫码确认。凭据只保存到私密存储；二维码失效后重新生成，不把历史“约五分钟”写死为协议保证。
5. 绑定完成后让用户先从微信发送一句“你好”。用该消息的有效回复上下文回信，等用户确认确实收到，再推进群聊能力。
6. 从用户的本机安装说明取得 CLI 入口与配置位置；通过已有本机执行工具运行 `--version` 和指定群一条历史消息，检查退出码、UTF-8 JSON、条数及 `failures`。
7. 用户指定会话与日期后获取完整本地记录，制作图片，并通过当前实际可用的图片发送能力发回微信。历史环境曾需要补充图片发送并拆分长图；这不是所有账号统一适用的尺寸限制。

不得在本轮教程任务中实际创建 routine、绑定账号、读取新聊天或发送微信；以上是读者按手册要求接入时的执行范围。

## 交给读者的说明

每次只交代一个必要动作，例如打开指定面板、复制一项信息到私密框、扫码、点确认、从微信发“你好”。找不到入口时依当前界面定位，不复用历史 automation ID、个人链接或截图。

本机连接信息由 WorkBuddy 或所选部署 Agent 生成不含密钥的说明。可包含用户自己机器上的入口与配置位置，供其在两个助手之间私下传递；不能公开放进教程或仓库。

## 故障恢复

| 现象 | Agent 检查 | 读者动作 |
| --- | --- | --- |
| 微信没有反应 | 接收程序是否运行、绑定状态与出站连接是否有效 | 修复后从微信再发“你好” |
| 能收到任务却回不去 | 当前回复上下文是否有效，区分实际错误原因 | 从微信发送新消息，再重发 |
| 凭据失效 | 按当前协议核对失效码；历史 `-14` 对应重新绑定 | 获取新二维码，扫码确认 |
| 图片发送失败 | 当前发送能力、图片体积和尺寸、可读性 | 查看分图后的实际收件结果 |
| 可以聊天但查不了群 | Windows 电脑在线情况、本机执行工具、CLI 用户与配置 | 按提示开启正确电脑或登录账号 |

历史上两次发生转发程序停止，重启后恢复；不能把运行一次描述成可长期自恢复。每小时检查曾被建议，但没有在所给材料中得到已启用的确认。默认提供手动恢复方法；建立定时任务或守护程序须有相应授权。

## GitHub 私有备份

这是可选的外部上传功能。用户登录自己的 GitHub，并明确指定群、时间范围及上传意图后，再创建或复用其私有仓库。

核对会话身份、分页、`stats.total` 与实际导出数。只上传指定记录；不上传 `all_keys.json`、配置、解密缓存或其他群。上传后重新读取远端文件核对中文和数量，再交付链接。不改写历史、不修改仓库可见性、不默认设每日自动备份。

公开代码仓库与私有聊天存档用途不同，任何公开文档都不得带入用户私有仓库地址或原始记录。

## 证据范围

本文使用的是已脱敏整理出的历史流程。对话导出记载了本机查询、微信文字收发和日报图片收件，但不是原始执行日志；不能据此声称本轮已经重测，或保证所有 Grok Bot 版本具备同样入口。当前腾讯官方项目支持的能力也不自动等于自定义转发程序已实现相同功能。
